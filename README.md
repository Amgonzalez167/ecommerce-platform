## Executive Summary

This case study demonstrates how a Project Manager can connect **business requirements, Jira work items, GitHub development activity, defect resolution, QA validation, and release readiness** in one delivery workflow.

A payment-gateway defect was tracked as **KAN-1**, providing a concrete example of issue identification, engineering handoff, implementation, and verification.

## PM Delivery Lifecycle

**Intake → Prioritize → Plan → Build → QA → Validate → Release → Learn**

| Stage | PM Responsibility | Evidence |
|---|---|---|
| Intake | Clarify business impact and acceptance criteria | Jira issue |
| Prioritize | Assess severity, urgency, and dependencies | Backlog / issue priority |
| Plan | Coordinate engineering and QA work | Sprint plan |
| Build | Track implementation progress | GitHub commits |
| QA | Confirm defect resolution and regression coverage | Test evidence |
| Validate | Confirm acceptance criteria | Jira / QA sign-off |
| Release | Coordinate deployment readiness | Release checklist |
| Learn | Capture lessons and process improvements | Retrospective |
